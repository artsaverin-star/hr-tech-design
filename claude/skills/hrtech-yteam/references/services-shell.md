## 1. Каталог «Сервисы»: выбрать известный рабочий инструмент

**Путь:** вкладка «Сервисы» → строка с названием и иконкой → целевой сервис/нативный экран → Back или закрытие модального экрана → исходная точка входа.

Список не является постоянной сеткой функций, зашитой в приложение. `GetWebServiceUseCase` получает каталог из Layout Manager, использует непустой кеш и резервный набор при отсутствии каталога. `WebServicesMapper` переносит из конфигурации названия RU/EN, иконки, хост, начальный путь, исключённые пути, способ открытия, видимость, настройки уведомлений и тип шапки. `ServicesRepository.servicesToShow` фильтрует список по `Yes`, `No`, либо `ByFlag`: разрешение сервера через Varioqub и/или включённый эксперимент разработчика. Порядок видимых элементов следует порядку источника.

`ServicesListViewModel` добавляет в конец «Экстренную помощь» и «Настройки». Для тестового аккаунта в этом ViewModel остаются только настройки. Строка целиком нажимаемая, с шевроном; доступное имя — название сервиса. Прочитанный `ServicesListScreen` не содержит поиска по каталогу, избранного, закрепления, пользовательской перестановки или группировки по задачам. Не проектировать новую функцию так, будто эти механизмы уже есть.

**Обновление и состояния:** `onShow` запрашивает обновление с допустимым кешем, pull-to-refresh — без него. Репозиторий имеет `isLoading` и `isExpired`; экран показывает `ExpiredToast` для устаревшей выдачи после загрузки. В прочитанном UI индикатор pull-to-refresh получает `refreshing=false`; это не доказательство отсутствия сетевого обновления. Иконка имеет запасной ресурс при ошибке загрузки. Пропавший пункт может быть следствием конфигурации/доступности/флага, а не переименованием раздела.

**Источники:** `KMP/features/services/ui/ServicesListViewModel.kt::{services,onServiceClick,onRefresh,onShow}`, `ServiceFormatter.kt`, `compose/ServicesListScreen.kt::{ServicesListScreen,ServiceItemView}`; `KMP/services/{ServicesRepository.kt,WebServiceUseCase/GetWebServiceUseCase.kt,WebServiceUseCase/WebServicesMapper.kt,WebServiceUseCase/WebService.kt}`.

Резервный каталог (`GetKpbWebServicesUseCase.kt`) содержит, в частности, профиль, Документницу, OK, Helpy и Карты офисов; Календарь, старые Карты и Формы могут быть описаны как невидимые пункты, оставаясь известными маршрутизатору. Это резервный клиентский набор, **не список того, что сейчас видят все сотрудники**. «Бенефиты», «Скидки» и другие строки реального каталога нельзя восстанавливать по одному резервному списку.

## 2. Оболочка встроенного сервиса: сохранить контекст и возврат

Клиент разделяет две задачи: открыть правильный сервис и обеспечить нативную оболочку. Внутренняя бизнес-операция обычно принадлежит самому веб-сервису.

| Сценарий | Результат и возврат в прочитанном iOS-коде |
|---|---|
| Внутренняя ссылка на известный сервис с `navigationStack` | Экран добавляется в стек текущей вкладки. Нативный Back снимает верхний экран этого стека. |
| Внешний диплинк на известный сервис | Клиент выбирает Календарь для календарного сервиса, Этушку для её сервиса, в остальных случаях «Сервисы», затем открывает экран. |
| Сервис с `sheet` | Используется модальный destination; при уже открытом модальном экране новое назначение ставится после его закрытия. Для отдельных IDM-ссылок применяется авторизованный SafariView. |
| Неизвестный веб-адрес | Последний обработчик может вернуть `ExternalBrowser`; неизвестная ссылка схемы `yteam:` намеренно не открывается во внешнем браузере. |
| Переход по `target=_blank` в веб-странице | `BrowserVC` передаёт URL штатному обработчику диплинков, не создаёт бесконтрольное второе WKWebView. |
| Повторное нажатие выбранной нижней вкладки | Действует существующий контракт: очистка стека; у Этушки дополнительно загрузка стартовой страницы, у Календаря пересоздание веб-сетки, у поиска на корне запрос фокуса. |

Есть по отдельному стеку для Home, Calendar, Search, At и Services. `goBackInCurrentTab` не является общей командой «всегда на главную». Для календарного перехода хранится `previousTab`, чтобы после выхода с последнего календарного экрана вернуться в прежнюю вкладку. Эти привычки нужно сохранять при встраивании нового сценария.

**Шапка и действия:** конфигурация сервиса задаёт default header; веб-код через bridge может менять заголовок, кнопки, селектор, запрашивать закрытие, поделиться, открыть URL, показать ошибку или нативное редактирование текста. Кнопка Back нативной шапки и кастомная левая кнопка с callback в JS — разные контракты. Не заменять их одной универсальной стрелкой без проверки потребителя. Присутствие метода bridge не означает, что его использует каждый сервис.

**Загрузка/авторизация:** Browser начинает с loading, ждёт readiness/init и имеет таймер ошибки загрузки; для обычного интегрированного navigation-stack сервиса сам `didFinishURL` не всегда означает готовность. Есть отдельные состояния ошибки сети и таймаута, действие повторной загрузки. Авторизация может обновлять cookies через невидимый WebView после запроса bridge или Passport redirect; одновременные запросы обновления объединяются. Сервис нельзя считать «без входа» лишь потому, что он открылся в браузерной оболочке.

**Источники:** `IOS/Features/Tabs/TabsView/TabsViewSystem.swift::{onDoubleTap,goBackInCurrentTab}`; `Reducer/TabsViewDeeplinkReducer.swift::{openDeeplinkType,openBrowser,openInCurrentTab}`; `IOS/Features/HRWebView/Reducer/{BrowserMainReducer.swift,BrowserNativeMethodReducer.swift,BrowserUpdateAuthReducer.swift}`, `BrowserErrorView.swift`, `BrowserVC/BrowserVC+WKUIDelegate.swift`; `KMP/services/deeplinks/{DeeplinkProcessor.kt,DeeplinkProcessorModule.kt,processors/DeeplinkWebServiceProcessor.kt}`.

## 3. Этушка: лента, публикация и обсуждение

**Точка входа в приложении:** отдельная вкладка At. `AtTabSystem.State.atService` выбирает конфиг `at-orbit`/`at-orbit-yango`; вкладка встраивает `BrowserSystem` как корень и сохраняет собственный стек. При отсутствии подходящего сервиса или ошибке загрузки конфигурации используется `AtErrorView` с повторной загрузкой. Внешний `yteam://atushka/...` распознаётся отдельным KMP-процессором и направляет в At; выбор сервиса зависит от Yango-инстанса.

**Что подтверждено выборочным чтением веб-фронта:** маршруты главной ленты, клубов, поиска клубов, конкретного клуба и его настроек, поста, создания/редактирования поста, создания клуба, профиля, клубов профиля и внутренних уведомлений. На странице поста загружаются пост, комментарии, агрегаты реакций и типы реакций; в шапке задаётся меню поста. Страница уведомлений устанавливает действие «прочитать уведомления» в шапке, а в app-контексте не дублирует его заголовок внутри контента.

**Пользовательские цепочки:** At → лента/клуб → пост с комментариями → возврат к ленте; At → создание публикации → редактор; At → уведомление → объект обсуждения. Последние два полных submit/return-пути в этом исследовании не пройдены: наличие маршрута редактора не доказывает право публикации и успешное сохранение. Правила доступа к закрытым клубам, удаления, модерации, черновиков и unsaved changes требуют чтения соответствующего контейнера/permission hook, а не выводятся из нативной вкладки.

**Источники:** `IOS/Features/Tabs/AtTab/{AtTabView.swift,AtErrorView.swift,Reducer/AtTabSystem.swift,Reducer/AtTabMainReducer.swift}`; `KMP/services/deeplinks/processors/DeeplinkAtushkaProcessor.kt`; `WEB/atushka/orbit/components/App/App.routes.tsx`, `components/pages/PostPage/PostPage.tsx`, `components/pages/NotificationsPage/NotificationsPage.tsx`. `WEB/atushka/AGENTS.md` указывает на `docs/overlays.md` для контракта закрытия оверлеев системным Back — прочитать перед изменением таких оверлеев.

## 4. Офис, карты, рабочее место и пропуск

### Найти место или ресурс

В приложении карта открывается как известный веб-сервис через каталог/диплинк; наличие карт отражается в `ServicesRepository.isMapsEnabled`. Старые Staff map-ссылки при наличии старого и нового map-сервиса преобразуются в объектные пути: здание, этаж, рабочее место, комната, переговорная, устройство, коворкинг. Отдельный флаг `IS_OFFICE_MAPS_CHANGE_URL_ENABLED` меняет адреса старого префикса `/office-maps` на новый хост; Yango использует свой домен.

В проверенных исходниках `office-maps` есть маршруты здания/этажа/ресурса/рабочего места/переговорной и валидаторы URL. Поиск бронирования различает initial/pending, успешный список, пустой результат со сбросом фильтров, ошибку с повтором и поддержкой. Действия для брони рабочего места включают изменение, отмену и показ на карте; они зависят от данных текущего пользователя и флага `SIDEBAR_WORKPLACE_BOOKING_SEARCH`. Нельзя показывать эти действия всем только по наличию карты.

**Путь, подтверждённый компонентами:** объект/список → карточка рабочего места или переговорной → выбор/подтверждение брони → состояние процесса → завершение или отмена; для переговорной есть отдельные callbacks ссылки в календарь и переноса процесса в фон. Полный набор правил конфликтов, прав на бронирование, лимитов и серверных отказов не исследован. После закрытия страницы сервиса нативная оболочка возвращает в её исходный стек; внутри страницы действуют веб-маршрутизация и её overlay/back-контракт.

Не путать рабочий сервис «Карты офисов» с нативным `SampleAppOfficeNavigationView`: последний содержит координаты, маяки, ручной выбор позиции и кнопки логов. Это диагностический sample-экран, а не доказательство готового массового сценария «проложить маршрут в любом офисе». Нативный `IndoorLocationManagerImpl` запрашивает when-in-use геолокацию и работает с beacon/heading; покрытие зданий и качество позиционирования не установлены.

**Источники:** `KMP/services/{OldMapToNewMapURLConverter.kt,ServicesRepository.kt,deeplinks/processors/DeeplinkWebServiceProcessor.kt}`; `IOS/Features/IndoorNavigation/{View/SampleAppOfficeNavigationView.swift,Reducer/SampleAppOfficeNavigationViewMainReducer.swift}`; `IOS/Services/IndoorLocationManager/IndoorLocationManagerImpl.swift`; `WEB/office-maps/src/app/lib/getRoutes.tsx`, `features/booking-search-list/BookingSearchListContainer.tsx`, `features/workplace-widget-actions/WorkplaceWidgetActionsContainer.tsx`, `features/conference-room-booking-process-modal/ConferenceRoomBookingProcessModalContainer.tsx`.

### Подтвердить проход по готовой ссылке

`yteam://pass?request_id=…&terminal_id=…` — отдельный сценарий: после проверки обязательных параметров iOS показывает KMP-шторку, а `PassViewModel` **сразу вызывает `submitPass`**. Открытие ссылки здесь является действием, а не просто просмотром. Состояния: Loading → Success/Error; закрытие скрывает шторку. UI ошибки содержит закрытие, отдельного retry в прочитанном экране нет. Поздний ответ не возвращает уже закрытую шторку. Обработчик явно отклоняет Yango.

Это не доказательство наличия нативного создания гостевого пропуска, постоянного QR-пропуска или единого раздела всех пропусков. Эти сценарии не исследованы и могут принадлежать другому веб-сервису.

**Источники:** `KMP/services/deeplinks/processors/DeeplinkPassProcessor.kt`; `KMP/features/pass/ui/{PassViewModel.kt,PassScreen.kt,dto/PassStateVO.kt}`; `IOS/Features/Tabs/TabsView/Reducer/TabsViewDeeplinkReducer.swift::openPass`.

## 5. Бенефиты, скидки, командировки и документы

### Льготы и скидки — два связанных, но не тождественных сервиса

Нативный каталог обеспечивает открытие настроенного адреса. Конкретный набор льгот и право на них определяет веб-сервис/сервер, не наличие строки в Team.

В выборочно прочитанном `benefits` маршрутизаторе есть главный кабинет, питание, документы, страхование, здоровье/психология/семья, добавление и продление страховки родственников, заём и калькулятор, скидки/категории/избранное. `Application.tsx` сопоставляет их страницам. Старые insurance routes перенаправляются в новый раздел; registry вне development перенаправляется на главную — не переносить dev-страницу в пользовательскую карту приложения. Модель пользователя принимает `benefits_access`, `benefits_cab_access`, `benefits_access_forbidden`, `discount_access` и ролевые признаки; **все правила их применения и доступность каждой льготы здесь не восстановлены**.

В отдельно прочитанном `discounts` подтверждены: главная → поиск/теги/категория/избранное → карточка предложения в Drawer → условия, срок, онлайн/офлайн, необходимость бейджика, промокод, контакт/ссылка партнёра → закрытие карточки и возврат к выдаче. Есть действия избранного, реакции и копирования промокода. Загружаемая карточка имеет skeleton и ошибку; главный App имеет ошибку страницы и not-found. Возврат/URL у мобильного и desktop Drawer различается; не подменять его нативной навигацией без проверки.

**Источники:** `WEB/benefits/src/application/router/{domain/domain.ts,root/router.ts}`, `modules/application/app/ui/Application/Application.tsx`, `modules/application/user/api/mapper.ts`; `WEB/discounts/src/router.ts`, `components/App/App.tsx`, `components/PageMain/PageMain.tsx`, `components/DiscountDrawer/{DiscountDrawer.tsx,DiscountDrawerContainer.tsx}`. Бизнес-сценарии выдачи кредита, страхования и выплаты не пройдены; эти файлы устанавливают границу возможностей и маршрутов, а не успех операции.

### Подготовиться к командировке и открыть документы

`TripFormatter` создаёт Home-виджет только для непустого списка поездок, выбирает актуальную поездку/сегмент, различает предстоящую поездку и оценку после неё. Нажатие заголовка открывает конкретную поездку или её feedback; анонс следующей поездки ведёт в сервис. Полёты, поезда и отели представлены отдельными доменными сегментами. Создание и изменение командировки внутри веб-сервиса здесь не исследованы.

**Путь документов:** виджет поездки → документы конкретной поездки → строка файла → нативный просмотр → Back/закрытие → список. Документы отображают downloading-started, downloading-progress с размером, downloaded и error. Нажатие готового файла открывает `file://`; ошибка предлагает повторную загрузку; на загрузке нажатие не открывает документ. iOS `openTripDocuments` добавляет экран именно в `mainTab.path` — это текущий конкретный контракт, а не универсальная гарантия открытия из любой вкладки. Подготовка Quick Look и удаление временного preview-файла находятся в маршрутизаторе/сервисе документов.

**Источники:** `KMP/features/trip/ui/formatter/{TripFormatter.kt,TripDocumentsFormatter.kt}`, `ui/DocumentsListViewModel.kt`, `domain/GetTripDocumentsUseCase.kt`; `IOS/Features/Tabs/TabsView/Reducer/TabsViewDeeplinkReducer.swift::{openTripDocuments,prepareFileURLForQuickLook,filePrepared}`.

«Документница» (`sign`) в резервном каталоге — отдельный веб-сервис с собственным push-событием нового документа. Просмотр скачанного файла из командировки не равен сценарию подписания документа. Содержимое Документницы/OK/Helpy не исследовалось.

## 6. Аккаунт, вход, onboarding и настройки

### Войти в рабочий контекст

**Путь:** экран входа → Passport UI → проверка корпоративного аккаунта → загрузка текущего сотрудника → подходящий onboarding или вкладки. На экране входа есть отдельный вход для нового сотрудника через welcome URL; ошибка авторизации предлагает путь поддержки и повторного выхода/входа. Сам UI менеджера Passport и двухфакторный вход не воспроизводились.

`AppMainReducer` различает неавторизованного пользователя, допустимый корпоративный аккаунт/аккаунт App Store review и неподходящий аккаунт. Существует флаг `REJECT_YANGO_ONLY_ACCOUNTS`, ограничивающий вход аккаунта только пространства Yango в Team. Наличие этого кода не говорит, что флаг включён. После logout очищается прикладной кеш, сбрасывается отложенный диплинк и открывается вход. Обычный экран выбора/переключения нескольких аккаунтов за пределами Passport в этом проходе не подтверждён.

При внешней ссылке уже авторизованный корпоративный пользователь получает нужный экран сразу после готовности приложения; холодный старт сохраняет ссылку и обрабатывает её после инициализации. Неавторизованному пользователю не сохраняют доступ к такому экрану автоматически.

**Источники:** `KMP/features/login/ui/LoginViewModel.kt`; `IOS/Application/Reducer/{AppMainReducer.swift,AppViewReducer.swift}`.

### Onboarding имеет условия, а не постоянное место в навигации

KMP сам выбирает onboarding: ещё не показанные встроенные вводные экраны и разрешение уведомлений, затем подходящий LM-onboarding. LM-контент зависит от platform enabled, диапазона версии приложения, `showOnStartup`, отметки «показан», наличия экранов и готовности изображений. При отсутствии подходящего контента оболочка закрывается. Явный ID открывается только для авторизованного пользователя и среди валидных onboarding. У контента есть действия закрытия, ссылки, push-разрешения и share; конкретная цепочка определяется данными, а не жёстко зашитыми рекламными карточками.

**Источники:** `KMP/features/onboarding/{ui/OnboardingViewModel.kt,data/repository/OnboardingRepositoryImpl.kt}`; `IOS/Application/Reducer/AppMainReducer+Onboardings.swift`; `IOS/Features/Onboarding/Reducer/OnboardingSystem.swift`.

### Настроить приложение и вернуться к работе

**Текущий iOS root** `SettingsView` рендерит `IOSSettingsRootScreen`, то есть KMP Settings root. Не использовать оставшийся `SettingsAppSection.swift` как доказательство видимого актуального состава экрана.

В `SettingsRootScreenViewModel` есть уведомления, часовой пояс, сброс/очистка, оценка приложения (кроме Yango), «О приложении», новости сервиса и выход. Часть пунктов скрыта для тестового аккаунта. Developer tools появляются после серии нажатий; это не пользовательская информационная архитектура. Выход требует диалога да/нет. Часовой пояс выбирается из списка, сохраняется через `TimezoneRepository`, затем экран возвращается назад. Нельзя путать timezone приложения с редактированием корпоративного календарного события.

**Источники:** `IOS/Features/Tabs/Settings/View/SettingsView.swift`; `KMP/features/settings/{root/SettingsRootScreenViewModel.kt,timezones/SettingsTimezoneViewModel.kt}`.

## 7. Уведомления и глубокие ссылки

**Задача:** открыть конкретный рабочий объект из уведомления и управлять тем, о чём приложение сообщает.

В iOS нажатый push с корректным URL и авторизованным корпоративным аккаунтом передаётся обычному маршрутизатору; при холодном старте ждёт инициализации. При push в foreground для календарного диплинка обновляется сетка событий — это не автоматическое открытие уведомления на весь экран. Внутренние уведомления Этушки остаются отдельным веб-сценарием.

Экран настроек уведомлений тоже встраивает KMP. Группы и события берутся из `servicesWithPushSettings`, поэтому их набор зависит от каталога сервиса. Есть системное разрешение, отключение целой группы и конкретного события. Отдельно показаны внутренние уведомления: предложение оценить приложение (не Yango) и предупреждение VPN; отключение VPN-предупреждения имеет подтверждение. Это настройка предупреждения, не обещание устранить сетевую проблему.

**Платформенное различие:** iOS репозиторий хранит отключённые события приложения и проверяет `UNUserNotificationCenter`; при ранее отказанном разрешении нужен переход в настройки ОС. Android дополнительно учитывает выключенные системные notification channels; попытка включить заблокированный канал отправляет пользователя в системные настройки. Календарная группа и канал напоминаний согласуются с CalendarLayersRepository. Не считать iOS и Android абсолютно одинаковыми только из-за общего KMP-экрана.

Внешний адрес может быть универсальной HTTPS-ссылкой (требуется OS association) или `yteam://…`. Обработчики упорядочены: настройки, поиск, onboarding, pass, файлы, документы поездки, indoor navigation, отсутствия, testing, видеоплеер, Services, Atushka, web service, Safari. Кастомная схема для известного web service может преобразоваться в HTTPS, но требует совпадения с каталогом; наличие произвольного `yteam://<имя>` не делает путь рабочим.

**Источники:** `IOS/Application/Reducer/AppNotificationReducer.swift`; `IOS/Application/App.swift::{onOpenURL,onContinueUserActivity}`; `IOS/Features/Tabs/Settings/View/Pushes/View/SettingsNotificationsView.swift`; `KMP/features/settings/notifications/SettingsNotificationsViewModel.kt`; `APP/shared/src/iosMain/kotlin/ru/yandex/team/app/shared/push/PushNotificationRepositoryIOS.kt`; соответствующий Android `PushNotificationRepositoryAndroid.kt`; `KMP/services/deeplinks/{DeeplinkProcessorModule.kt,processors/DeeplinkBaseProcessor.kt}`.

## 8. Восстановление после ошибки

| Ситуация | Подтверждённый путь восстановления | Что нельзя обещать |
|---|---|---|
| Веб-сервис не загрузился/нет сети/истёк таймаут readiness | Ошибка в оболочке и повторная загрузка; нативный выход остаётся в навигации | Работа всего сервиса офлайн; исчезновение серверной ошибки после retry |
| Сессия веб-сервиса устарела | Обновление cookies через auth bridge/Passport flow, затем повторная загрузка или ответ обещанию веб-кода | Что повторный вход никогда не потребуется |
| Список сервисов устарел | Кеш, ExpiredToast, обновление на показе или жестом | Что устаревшие данные равны актуальным правам/наличию сервисов |
| Не загружается документ поездки | Состояние error у файла, повторная загрузка отдельного файла | Что файл можно открыть до завершения загрузки |
| Нужно очистить локальные данные | Настройки → очистка: отдельные операции onboarding, LM-кеш, cookies, WebView-кеш, статика Календаря; операции имеют подтверждения/состояния | Что это безвредный универсальный первый шаг: WebView-clear удаляет также local/session storage и базы |
| Аварийная конфигурация Home/профиля | Существующий контракт `app-emergency`/Varioqub, отдельные Team/Yango поля; профиль может замениться Фениксом | Что это обычная продуктовая фича или сейчас включённый режим |
| Блокирующее обновление приложения/VPN | AppMainReducer отдаёт приоритет hard update, затем VPN-экрану | Что смена дизайна экрана решает причину блокировки |

Аварийный Staff Phoenix заменяет/дедуплицирует соответствующие пункты профиля и переадресует известные профильные ссылки; не перехватывает произвольные административные Staff-маршруты. Аварийное поведение зависит от LM-кеша и Varioqub, сеть не доставляет новые команды при полном отказе. Это описано в `APP/docs/emergency/README.md` и реализовано в `GetWebServiceUseCase`/`DeeplinkWebServiceProcessor`.

**Источники очистки:** `KMP/features/settings/clear/SettingsClearViewModel.kt`; `APP/shared/src/iosMain/kotlin/ru/yandex/team/app/shared/features/settings/clear/IOSWebviewRepository.kt`. Данные аккаунта и кеш в исследовании не очищались.

Наши preview-строки Services и `WebService.mars` не доказывают содержание серверного
каталога или выкатку сервиса. Адаптер списка не регистрирует сервис автоматически во всех
маршрутизаторах. История конкретной интеграции вынесена в

## 10. Покрытие и оставшиеся пробелы

| Область | Глубина прохода |
|---|---|
| Каталог Services, модель сервисов, LM/fallback/visibility | Прочитан путь источник → formatter → список → router |
| iOS web-shell, загрузка, Back, смена вкладки, auth refresh, ошибка | Прочитаны основные reducer/view/bridge участки; не все native SDK методы и обработчики файлов |
| Atushka | Нативная вкладка/ошибка/диплинк; веб-роуты, страница поста и уведомлений. Не полный submit/permissions editor flow |
| Office maps / workplace | Нативная маршрутизация и legacy URL; веб-роуты, состояния поиска брони, действия рабочего места, процесс переговорной. Серверные права/конфликты не восстановлены полностью |
| Pass | Полный небольшой native/KMP путь: параметры → submit → loading/result/close; не все пропускные продукты |
| Trips/docs | Home formatter → выбор поездки/документов → состояния файла → просмотр; веб-редактирование поездки не исследовано |
| Benefits | Маршруты → страницы и поля доступов; не весь кабинет, eligibility и заявки |
| Discounts | Главная/поиск/теги, маршруты, карточка/действия/закрытие; не весь API и серверные ограничения |
| Account/onboarding/settings/push | Основной iOS жизненный цикл и KMP UI; отдельное сравнение push repository iOS/Android |
| Emergency/recovery | Документированный контракт и ключевые callers; публикация конфигурации не выполнялась |

Не проверены: фактическая выдача LM и значения флагов; продовые версии веб-бандлов; Android activity/navigation shell целиком; гостевые/приглашённые аккаунты вне явных условий; условия документов/подписания/согласований, полные Helpy/OK/Документница/события/обучение; поведение каждого раздела без сети; текущая доступность всех перечисленных маршрутов у конкретного пользователя; полноценные runtime-проходы. В будущей задаче сначала открыть owning container/reducer именно затронутого сценария и дополнить эту карту, затем менять интерфейс.

## Продуктовые ограничения, вытекающие из кода

1. Новый сервис должен иметь понятный постоянный вход и корректный повторный вход. Исчезающая карточка конкретного события не заменяет точку входа в раздел.
2. Каталог и контекстная ссылка решают разные задачи. Карточка объекта может открывать объект; пункт с именем раздела должен вести к ожидаемому разделу, а не случайно сохранённой детали.
3. Вкладка, её повторное нажатие, стек Back, ссылка из push и внутренняя ссылка — отдельные пользовательские контракты. Изменение одного не даёт оснований менять остальные.
4. Поиск, календарь, лента обсуждений и каталог уже имеют свои сценарии. Нельзя переносить или переименовывать их только потому, что новый инструмент тоже умеет искать, обсуждать или работать со встречами.
5. Название и соседство должны объяснять функцию. Календарное расписание, материалы прошедшей встречи и бронь переговорной связаны, но не являются одним экраном/одними данными.
6. Наличие сервиса, флага, bridge API или frontend route — основание исследовать функцию, не обещать её пользователю. Штатный каталог, выбранный инстанс и локальный эксперимент описываются раздельно.
