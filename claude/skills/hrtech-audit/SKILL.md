# Проверка на ДС (аудит + починка)

Работаем ТОЛЬКО через мост Булочки (`figma-hrtech`, `figma_execute`). Официальный Figma-MCP
(`mcp__figma__*`) не трогать даже на чтение. Единственное исключение — разово достать `componentKey`
неизвестного компонента из опубликованной библиотеки (`search_design_system`), дальше снова Булочка.
Мост отвалился → ждать / просить переоткрыть плагин, не искать обход.

Очередь задач, статус-протокол, каталог ключей компонентов, `hrtechScan`/`hrtechDiff` и общие
layout-гочи — в `claude/commands/hrtech.md` и `claude/commands/hrds-knowledge.md`. Здесь только аудит.
Первый `figma_execute` сессии — проверка `hrtechVersion` (см. hrtech.md, п. 0a2).

## Чек-лист: что ищем

1. **Хардкод-заливки вместо токенов** — SOLID-краска без `paint.boundVariables.color`. То же для
   `strokes`. Признак: белый/серый/чёрный RGB руками.
2. **Голые размеры вместо текст-стилей** — `textStyleId` пустой ИЛИ `null` (отвязан — именно так
   выглядит инстанс с отвязанным стилем), `typeof textStyleId === 'symbol'`
   (mixed = частично отвязан), либо стиль из группы `🚫 Figma/*` (deprecated, не использовать).
3. **Кустарные псевдокомпоненты** — прямоугольник + текст, изображающие кнопку/тег/чип/строку списка.
   Голые FRAME допустимы ТОЛЬКО как невидимые структурные контейнеры.
4. **Отвязанные / чужие инстансы** — узел, который должен быть HRDS-инстансом, а на деле FRAME; или
   инстанс локального дубля вместо библиотечного компонента.
5. **Плейсхолдеры** — тексты `Label`, `Слот`, `Название встречи` (но НЕ «Caption»: так называется
   и слой, и текст-стиль `Caption/M`); иконка-заглушка **`Bug`** в
   правой кнопке `❇️ Header [mobile]` (проп `← Icon#29143:237`); пустой `Slot ←#23968:97` у `Tag · Status`
   (рисуется полым кольцом → поставить Empty-филлер `f2c18c9fa5290e9ea352d38cc6cc3a51b61ce986`).
6. **Голая иконка в слоте** — в слот кладут 💠-филлер, не вектор: у `❇️ Button` левый `Slot ←#23968:97` =
   `Button / 💠 Icon` `054cdf002d8efef15e9912df1972418b8a2e221c` (внутрь него `← Icon#616:5`, Size=16);
   у `Tag · Dropdown` «+» = `💠 Icon Button · Preset=Add` `8ffecb7fe089984498a266ecb550e49e249dbe28`.
   Иконка самой icon-кнопки — её собственный проп `← Icon#29143:237`, а не слот.
7. **Забытые оверрайды** — `inst.overrides` с `textStyleId`/`fills` в `overriddenFields`: такой инстанс
   больше НЕ слушает мастера. Плюс carry-over цвет после свапа (синий link/accent на `← Label` кнопки).
8. **Мелочи ДС** — мобильные контролы должны быть Size=M (40), не S; чекбокс не в mixed-состоянии
   (`Selected=on|off` + `Mixed=off`); дизейбл/лоадинг — реальные `State=Disabled|Loading`, а не `opacity 0.4`.

## Как сканировать, не вешая песочницу

Песочница однопоточная, скрипт не прервать; `figma_execute` живёт ~7–10 с. Правила обхода:

- Скан исходника — встроенным `hrtechScan('<frameId>')`, свой tree-walker не писать.
- НИКОГДА `loadAllPagesAsync()` и `findAll` по всей странице. Скоуп — конкретный фрейм.
- `frame.findAllWithCriteria({types:['INSTANCE']})` пофреймово + сбор уникальных `.name` — рабочий
  способ понять, из чего собран экран. На тяжёлой секции `findAllWithCriteria` **вешает мост** → DFS
  с бюджетом узлов и **проверкой `budgetLeft` на выходе**: ушёл в 0 — обход обрезан, часть узлов не
  проверена (секция ~60 000 узлов при бюджете 30 000 нашлась наполовину). Гонять, пока не вернёт 0 новых.
- `getStyledTextSegments` не звать в цикле по многим узлам.
- Каждый RETURN < 15 КБ: возвращай сводку `{id, name, что нарушено}`, не дамп узлов.
- `figma.skipInvisibleInstanceChildren = true` ускоряет `findAll`, но **прячет невидимые узлы** — для
  аудита плейсхолдеров ставь `false`, для быстрого прохода по видимому — `true`.
- `node.mainComponent` под `dynamic-page` кидает — только `await node.getMainComponentAsync()`.

Скелет детектора (одним вызовом на фрейм, с капом):

```js
const f = await figma.getNodeByIdAsync('<frameId>');
const bad = { fills: [], text: [], ovr: [], ph: [] };
const stack = [f]; let budget = 30000;   // проверено: 30 000 хватает на секцию ~60 000 узлов
while (stack.length && budget-- > 0) {
  const n = stack.pop();
  if (n.fills && Array.isArray(n.fills))
    for (const p of n.fills)
      if (p.type === 'SOLID' && p.visible !== false && !p.boundVariables?.color) bad.fills.push(n.id);
  if (n.type === 'TEXT') {
    if (!n.textStyleId || typeof n.textStyleId === 'symbol') bad.text.push([n.id, n.name]);  // '' и null — оба «отвязан»
    if (/^(Label|Слот|Название встречи)$/.test(n.characters.trim())) bad.ph.push([n.id, n.characters]);  // «Caption» НЕ сюда: это имя слоя и текст-стиля Caption/M
  }
  if (n.type === 'INSTANCE' && n.overrides?.some(o =>
      o.overriddenFields.includes('textStyleId') || o.overriddenFields.includes('fills')))
    bad.ovr.push([n.id, n.name]);
  if (n.children) for (const c of n.children) stack.push(c);
}
return { budgetLeft: budget, ...bad };
```

`budgetLeft <= 0` → результат неполный, повторить с продолжения.

## Быстрый тест на хардкод: тёмная тема

Токены — не самоцель, юзер проверяет их переключением темы. Хардкод-заливка не перевернётся.

```js
const v = await figma.variables.importVariableByKeyAsync('b8ab79aed2ffe341815df5ec3512a0b22a7caf5d'); // surface/0
const coll = await figma.variables.getVariableCollectionByIdAsync(v.variableCollectionId);            // Palette
const inv = coll.modes.find(m => /inverse/i.test(m.name)).modeId;                                     // Inverse = тёмная
frame.setExplicitVariableModeForCollection(coll, inv);
// скриншот → белые/серые пятна = хардкод; потом
frame.clearExplicitVariableModeForCollection(coll);
```

Ключи токенов: `surface/0` `b8ab79aed2ffe341815df5ec3512a0b22a7caf5d` (это **серый #F5F5F5**, а не белый —
подложка/утопленная плашка) · `surface/100` `34df39284f093bc81cbbb984c5d561f555f0559c` (белый) ·
`surface/200` `064ba00db5c35d1bc8f8eaf742742824a83b3bfc` (белый) · `text/primary`
`1ade4d13d6d3bb5e20d89deb79d7e394bceb80cf` · `text/secondary` `290b7729c16d7df29d46f033a03f137c5a87d80d` ·
`text/tertiary` `520dff536c7e498a2569229299e9ab13637a06ef` · `border/secondary`
`d26976769b3bf424019df03d0dfa1977ba06dc75` · `border/tertiary` `7d67def723b733011746190d285225ac64b63151`.

Привязка найденного хардкода:
`n.fills = n.fills.map(p => p.type==='SOLID' ? figma.variables.setBoundVariableForPaint(p,'color',v) : p)`
(так же для `strokes`). Отступы — `n.setBoundVariable('itemSpacing'|'paddingTop'|…, spaceVar)`.

Текст-стиль на отвязанный узел: возьми `textStyleId` у соседнего правильного узла (локальных стилей в
файлах НЕТ, они remote — `getLocalTextStylesAsync()` пустой) и примени тот же in-file id через
`await t.setTextStyleIdAsync(id)` / `setRangeTextStyleIdAsync(start,end,id)`. Перед правкой текста грузи
ВСЕ шрифты ренджей: `for (const fn of t.getRangeAllFontNames(0, t.characters.length)) await figma.loadFontAsync(fn)`.

## Правь МАСТЕР, а не оверрайд инстанса

Жёсткое требование владельца ДС: «надо в мастере, не оверрайдом». Порядок:

1. `const main = await inst.getMainComponentAsync()`; мастер набора — `main.parent` (COMPONENT_SET).
2. `main.remote === false` → мастер локальный, правь его напрямую (и каждый вариант набора).
3. После правки мастера **сбрось оверрайд на инстансе** (`inst.resetOverrides()`), иначе он продолжит
   показывать старое. Reset скоупится на узел — оверрайды соседних узлов не теряются.

**Когда неприменимо:**
- `main.remote === true` → это библиотечный HRDS, отсюда view-only. НЕ хачить оверрайдом: оформляй
  запрос/правку в ДС-файле (ветка библиотеки), в макете фиксируй как замечание.
- **Контент** (`characters`) — он и ДОЛЖЕН быть оверрайдом инстанса, это не нарушение.
- **Вложенные варианты**: строка с переключённым `Type` берёт базовый стиль из СВОЕГО варианта-мастера
  набора — правка родительского мастера на неё не влияет by design. Чинить в этом варианте набора.
- Нужна новая строка/элемент в общем мастере, но старые экраны трогать нельзя →
  `key = master.addComponentProperty('NDA','BOOLEAN', false)` + `row.componentPropertyReferences = {visible:key}`:
  default `false` прячет её во всех существующих инстансах, новые экраны включают явно.

## Рецепт: снять залипший оверрайд (мастер поменяли — инстансы не обновились)

Причина — ручной `textStyleId`-оверрайд на тексте инстанса; оверрайд всегда перебивает мастера.
**`setRangeTextStyleIdAsync` со стилем, РАВНЫМ мастеру, флаг НЕ снимает** — только настоящий сброс:

1. Снять снапшот с инстанса: `componentProperties`, `primaryAxisSizingMode`, все `visible`-оверрайды
   (id + значение), тексты с `characters`-оверрайдом (id + строка).
2. `inst.resetOverrides()` (есть только у INSTANCE; на вложенных работает, сбрасывает поддерево).
3. Вернуть: `setProperties(props)` → pasm → видимости → `t.characters = …` (простое присвоение
   `characters` НЕ регистрирует `textStyleId`-оверрайд, это проверено).
4. Проверка: `inst.overrides.some(o => o.overriddenFields.includes('textStyleId')) === false`.

## Рецепт: чистка после свапа компонента

- **Порядок обязателен: сперва мастер, потом reset инстанса.** `resetOverrides()` на вложенном инстансе
  ОТКАТЫВАЕТ и сам swap — свап хранится как оверрайд родителя.
- После swap остаются унаследованные цвета (баг: `❇️ Link` → `❇️ Button` оставил синий link/accent на
  `← Label`, кнопка читалась самодельной). Фикс: взять родной fill из целевого варианта
  (`variant.findOne(n => n.name === '← Label').fills`) и присвоить узлу инстанса.
- Лейбл и свап слота — **разными** вызовами `setProperties`: в одном вызове лейбл молча остаётся «Label».
- Замена кустарщины на настоящий компонент: `importComponentByKeyAsync` / `importComponentSetByKeyAsync`,
  у SET брать КОНКРЕТНЫЙ вариант-ребёнок. Первый (холодный) импорт может выбить таймаут — просто
  повторить, прогретый кэш отвечает мгновенно.
- Финальная проверка — скриншотом: должен получиться pristine DS-компонент, а не гибрид.

## Что НЕ считать нарушением (частые ложные срабатывания)

- **ЗАЛИВКИ ВНУТРИ ДС-ИНСТАНСОВ.** Компоненты HRDS уже привязаны к токенам и сами переключаются в
  тёмную тему — их внутренние краски флажить НЕЛЬЗЯ. Пункт 1 чек-листа относится ТОЛЬКО к
  рукодельным узлам: поднимись от найденной краски вверх и, если по дороге встретился INSTANCE
  библиотечного компонента, пропусти. Без этого отчёт утонет в ложных срабатываниях.
- **Мод `Static` у Palette.** Модов три — Default / Inverse / **Static**. Узел на Static законно НЕ
  переворачивается в тёмной теме, это не хардкод.
- **`black@0.04`** — легальная заливка плашки наравне с `surface/0`.

- **Плашка/карточка/информер.** В HRDS такого компонента НЕТ (проверено сканом ~2000 инстансов).
  Плашка по ДС = ПОВЕРХНОСТЬ: фрейм с fill-токеном `surface/0` + радиус + ДС-контент внутри (текст на
  textStyleId + цвет-токены, действие = icon-button). Это примитив ДС, не кустарщина. Обратное тоже
  верно: `💠 List-Item` — для СТРОК списка, самостоятельной плашкой его быть не должно.
- **Литеральный радиус.** Общего токена скругления в ДС нет (только per-control внутри `🚫 Control · Size`)
  — радиус кастомной поверхности остаётся числом, не флажить.
- **Оверрайд `characters`** — легальный контент-оверрайд.
- **Косметика, которая уже в проде** (отступы/выравнивание/позиция ✕) — юзер просил такие ниты не носить.

## Гочи

- **Эффективная видимость.** `node.visible === true` ничего не значит: узел может быть скрыт выключенным
  РОДИТЕЛЕМ (или булев проп `has Caption`/`has Footer` = false у обёртки). Проверяй цепочку вверх до
  экранного фрейма — узел виден, только если видимы ВСЕ предки. Иначе «починишь» невидимое и отчитаешься
  о несуществующем результате. Тот же корень у обратного: `skipInvisibleInstanceChildren=true` просто не
  покажет тебе скрытые плейсхолдеры.
- **ГОНКА ФОНОВЫХ `figma_execute` (была реальная порча данных).** Затаймаученный вызов ПРОДОЛЖАЕТ
  работать в фоне. Перезапуск того же батча = два скрипта наперегонки делают snapshot→reset→restore и
  **перетирают восстановленные тексты плейсхолдерами мастера** (уползло ~8 названий встреч). Правила:
  (1) reset-батчи мелкими порциями — **≤6 инстансов на вызов**, таймаут 30 с; (2) после таймаута НЕ
  перезапускать сразу — сначала read-only проба состояния через ~30 с; (3) перед деструктивным батчем
  снять полный дамп текстов фрейма (id + `characters`) как страховку и логировать его.
- **`t.characters = …` убивает пораздельное форматирование.** Массовая правка опечатки через
  `characters.replace(...)` сплющила богатый текст (52 стиль-сегмента) в один стиль первого символа.
  Точечная правка внутри форматированного узла — `insertCharacters(i,'К','AFTER')` / `deleteCharacters`.
  Детектор порчи: `getStyledTextSegments(['fontName','fontSize']).length === 1` на длинном тексте.
  Донор для восстановления — узел МАСТЕРА компонента (оверрайд портит только инстанс).
- **`exportAsync` встаёт колом после массовых правок**: `figma_execute` отвечает за 5 мс, скриншот —
  таймаут 30 с. Это не поломка моста, рендер-очередь разгребается сама за 2–5 минут. Не откатывать
  правки в панике. Проверка «жив ли экспорт» — экспорт крошечного временного прямоугольника.
  Скриншоты кэшируются по (nodeId, scale) — чтобы получить свежий рендер, сдвинь scale.
- **Скелетоны/плейсхолдер-блоки** заливай видимым токеном `border/secondary`, а не `surface/200` —
  белое на белом читается как пустая дыра, и аудит примет это за пропущенный блок.
- `node.placeholder = true` в этом окружении не ставится (кидает `object is not extensible`).

## Отчёт

Итог — списком «нарушение → id узла → что сделано / что требует ДС-файла». Отдельно вынеси то, что
не починил, потому что мастер `remote === true`. В конце — скриншот исправленного фрейма и, если
правил тексты, `hrtechDiff` (см. hrtech.md, п. 0a3), чтобы доказать, что ничего не выдумано.
