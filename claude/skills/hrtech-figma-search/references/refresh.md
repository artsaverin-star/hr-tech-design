# Локальный каталог и обновление

Скрипты работают без внешних зависимостей. Перейди в реальный каталог умения
`hrtech-figma-search` и выбери `BULOCHKA_NODE` по [инструкции запуска](runtime.md).

## Хранение на компьютере сотрудника

По умолчанию каталог создаётся в
`~/.hrtech/figma-catalog/978907722219265370/catalog.json`, индексы — рядом, в `indexes/`.
Каждый сотрудник получает данные через собственный Figma-доступ. Пакет Булочки не
содержит частный каталог; переустановка или обновление умения его не заменяют.

Чтобы использовать уже собранный каталог, запиши локальный JSON-конфиг
`~/.hrtech/figma-catalog.json` с абсолютным путём:

```json
{"catalogPath":"/absolute/local/path/catalog.json"}
```

Другие способы: `BULOCHKA_FIGMA_CATALOG=/absolute/local/path/catalog.json` или аргумент
`--catalog /absolute/local/path/catalog.json` у обеих команд. Приоритет:
`--catalog` → переменная окружения → конфиг → стандартный путь.
При переносе каталога сохраняй рядом весь `indexes/`: `indexPath` внутри JSON относительный.
Для другой команды Figma передай `--team TEAM_ID` и отдельный `--catalog` при обнаружении;
в поиске укажи тот же каталог.

## Доступ

Сканер читает существующий токен из `~/.hrtech/figma-token` (настройки Булочки), затем
использует `FIGMA_ACCESS_TOKEN`, если локального токена нет. Не передавай токен аргументом
команды и не сохраняй его в каталог, логи или умение. Нужны scopes `folders:read` и
`file_content:read`. Токен используется только для GET-запросов к `https://api.figma.com`.
Если токен отсутствует или доступ отклонён, покажи конкретную ошибку и предложи настроить
личное подключение в Булочке; не переноси чужой токен или индекс на компьютер сотрудника.

## Первый запуск и нужные файлы

```sh
"$BULOCHKA_NODE" scripts/scan.mjs discover
"$BULOCHKA_NODE" scripts/search.mjs "календарь" --type FILE
"$BULOCHKA_NODE" scripts/scan.mjs scan --file FILE_KEY --depth 2
"$BULOCHKA_NODE" scripts/search.mjs "встреча" --file FILE_KEY
"$BULOCHKA_NODE" scripts/scan.mjs page --file FILE_KEY --page PAGE_ID
"$BULOCHKA_NODE" scripts/search.mjs "запрос" --file FILE_KEY
"$BULOCHKA_NODE" scripts/scan.mjs status
```

`discover` обходит корневые и вложенные папки и получает реестр файлов и веток без чтения
всего содержимого. После этого сразу доступен поиск файлов по названиям. Для поиска внутри
макета дочитай только подходящие файлы: `--depth 2` сохраняет страницы и верхние объекты,
`--depth 3` — ещё один уровень. `page` читает одну выбранную страницу целиком.
Полное дерево одного файла: `scan --file FILE_KEY --depth 0`; оно включает доступный текст
слоёв и может требовать существенного времени и памяти. Массовый полный скан для первого
запуска не нужен. Пустая выдача реестра не означает отсутствие текста внутри макетов.

Если Figma отвечает `Request too large`, сканер сохраняет список страниц и указывает
`limitedReason` и фактическую `depth: 1`. Дочитай нужную страницу через `page`.
`partial` и `pageDepths` показывают её покрытие. При изменении версии файла между чтениями
`staleOtherPages` помечает старые страницы; обнови нужные страницы отдельно.

## Возобновление и ограничения API

Успешно прочитанный файл сохраняется сразу. `--limit N` ограничивает число файлов прохода,
`--force` перечитывает существующий индекс. Повторный `scan` пропускает сохранённые файлы
с достаточной глубиной. Чтобы узнать об изменениях, обнови реестр через `discover` или
перечитай выбранный файл с `--force`. Не запускай несколько процессов записи в один каталог.
`--workers 1..8` допускает параллельное чтение структуры; полное дерево читается одним
worker. `--interval-ms` задаёт интервал запросов.

При `429` сканер сохраняет прогресс, выводит `Retry-After` и останавливается. Возобнови
после указанного срока. Не обходи лимит другим токеном. `--rate-limit-retries 3` включает
до трёх повторов одного запроса, только если `Retry-After` не больше 60 секунд.
При `403`/`404` показывай недоступность файла и неполное покрытие. Ошибка сети или усечённый
ответ не являются успешным сканированием. Удаление старых записей при `discover` происходит
только после успешного обхода всех папок.

## Локальная сжатая копия

При необходимости уменьши размер локальной резервной копии:

```sh
"$BULOCHKA_NODE" scripts/pack.mjs --source /absolute/local/catalog.json --destination /absolute/local/backup/catalog.json
```

Каталог остаётся обычным JSON, индексы сжимаются gzip внутри JSON-envelope.
`search.mjs` и `scan.mjs` читают оба формата. Новый каталог публикуется атомарно после
записи всех индексов. При изменении исходного индекса повтори упаковку после завершения
сканирования. Старые поколения автоматически не удаляются.

Каталог, индексы, отчёты о покрытии и токены остаются локальными: не добавляй их в Git,
исходники умения или релиз Булочки. Обычное обновление каталога не требует релиза.

## Первичные источники API

- [Папки и вложенные папки](https://developers.figma.com/docs/rest-api/folders-endpoints/)
  — `/v2/teams/:id/folders`, `/v2/folders/:id/folders`, `/v2/folders/:id/files`.
- [Дерево файла и глубина](https://developers.figma.com/docs/rest-api/file-endpoints/)
  — `/v1/files/:key`, отсутствие `depth` означает полное дерево.

Старые `/v1/teams/:id/projects` требуют другого scope и не раскрывают вложенные папки.
Для этого каталога используй v2 folders.
