# Комплект «Карта» v6 — что копировать в прототип

> Вида «Сценарий» (`?spec=1`, `ScenarioView`) нет и не будет: владелец 6.10.2026 — «удали вкладку
> «Сценарий» и больше его никогда не делай». В «Вид» — только «Прототип» и «Карта».

Движок сверен 7.10.2026 с «Я Team & MARS: сайт и приложение — версия 6» (Прототипница,
`prototypes/intranet/orbit/mars-v-prostranstve/intranet-orbit-artsaverin-ya-team-mars-sayt-i-prilozhenie-versiya-6/`,
опубликован в trunk; 10 секций, 171 кадр) и доучен на нём: телефон без десктопной
пары (экран нативного приложения) — полноправный узел карты с якорями кнопок. Комплект лежит в
скиле, чтобы установка не зависела от чужого прототипа: у эталона своя панель «Режим · Вид» и
свой `SpecView`. Правишь движок в прототипе — обнови и эту копию (тот же коммит), иначе комплект
разъедется с эталоном. Прогнан на двух чужих прототипах витрины (обычный корень
`PrototypeProviders` → `PrototypeDraft`, демо-панель состояний).

## 0. Установка одной командой

```bash
node <скил>/references/kit/scripts/spec-kit-install.mjs --to <папка прототипа>
```

Скрипт копирует движок, виды и скрипты, кладёт заготовки `spec.ts`, `spec-sections.ts`,
`spec-seeds.ts`, `spec-snapshots.json` (только если своих ещё нет — свои файлы продукта он не
перезаписывает никогда), САМ вписывает `<SpecGate>` в стандартный `src/index.tsx` и строку
`import './spec-seed-runtime';` (чистый старт рецептов, см. ниже), помечает
`data-spec-chrome` узнанную демо-панель прототипа, говорит, если
в прототипе уже лежит СТАРЫЙ движок, и печатает следующие шаги с готовыми командами. Повторный
запуск безопасен; `--force` перезаписывает только файлы движка (например, после обновления скила).
Дальше — регламент в `SKILL.md` §0.

Заготовки лежат в `templates/`. `examples/` — только ЧИТАТЬ: это продуктовые файлы эталона v6
(секции «Скиллы» и «Приложение» с телефонами без пары, общий вход рецептов `APP_OPEN`); они
импортируют модули MARS (`./model`, `./spec-live`, `./texts/*`) и в другом прототипе не соберутся.

## 2. Написать самому (заготовки — `templates/`), в этом порядке

| файл | что в нём |
|---|---|
| `spec-seeds.ts` | рецепты шагов: «Готовый рецепт» из разведки один в один; экспорт `SEED_RECIPES`, `SEED_IDS` |

## 3. Подключить в прототипе

- **Вид и рецепты** — `<SpecGate title="…">` ВНУТРИ `PrototypeProviders` в `src/index.tsx`
  (установщик вписывает сам, если корень стандартный). Проверка: `spec-snapshots.mjs --wiring` —
  три строки «✓». У прототипа своя панель режимов (как у «Я Team & MARS») — рендери там
  `<SpecView title="…" />`, когда в адресе есть `spec`, а в переключателе «Вид» — только «Прототип»
  и «Карта»; повтори нужное из SpecGate (`motion=off`, запуск рецептов, `data-spec-chrome`).
- **Демо-панель** (ряд переключателей сценариев над продуктом) — атрибут `data-spec-chrome` на
  контейнере (установщик ставит сам, если узнал; `--wiring` проверяет): на кадрах она прячется после
  того, как рецепт её нажал, а её кнопки не годятся в `label` переходов.
- **Рецепты с `actions`** (вариант А, модель с редьюсером) — две строки в модели прототипа: точный
  текст в шапке `templates/spec-seeds.ts`. Без редьюсера ничего не нужно: рецепты из `clicks`
  запускает SpecGate.
- **Чистый старт рецептов** — строка `import './spec-seed-runtime';` в `src/index.tsx` (вписывает
  установщик): с `seed` движок подменяет `localStorage`/`sessionStorage` памятью страницы раньше, чем
  продукт что-то прочитает. Прототип хранит состояние иначе (IndexedDB, cookie) — точечная проверка
  `hasSpecSeed()` в модели, с ведома владельца.
- Заморозка живых таймеров (прогон, отсчёт) параметром адреса — у эталона `&tick=1`.

## 4. Проверить

```bash
node src/scripts/spec-snapshots.mjs --base https://prototipnitsa.local.yandex-team.ru:<порт>/prototype-builds/<slug>/ --wiring
node src/scripts/spec-snapshots.mjs --base <адрес> --probe '?'
node src/scripts/spec-snapshots.mjs --base <адрес> --explore '?'
node src/scripts/spec-lint.mjs
node src/scripts/spec-snapshots.mjs --base <адрес> --prune --sheet /tmp/spec-sheet.png
node src/scripts/spec-map-check.mjs --base <адрес> --shots /tmp/spec-shots
```

`--probe` — разведка: дословные кнопки и поля экрана на 1440 и 375 (тексты для `label` и
`clicks` берутся только отсюда), с `--click` — путь и «Готовый рецепт». `--explore` — что меняет
каждая кнопка. Генератор падает (код 1) на сломанном или неподключённом рецепте, одинаковых
кадрах и телефоне-обрезке и рисует лист-сетку — её нужно посмотреть глазами. Приёмка падает на
любом дефекте, а если карта не открылась — с кодом 2. Сообщения скриптов разобраны в
`../view-modes.md`, «Симптом → причина → что делать». Плюс из корня витрины:
`node_modules/.bin/tsc -p prototypes/<…>/<slug>/tsconfig.json --noEmit`,
`node_modules/.bin/eslint --quiet prototypes/<…>/<slug>`, `node scripts/hrds-check.mjs prototypes/<…>/<slug>`
и `node scripts/repository-check.mjs`.
