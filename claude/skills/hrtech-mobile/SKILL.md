## Примеры

- «переведи этот экран на мобилку»
- «замени попап на шторку»
- «посади текст на ДС-стили»

Плейбук очереди, статус-протокол, каталог ключей HRDS и общие гочи Plugin API — в
`claude/commands/hrtech.md` (разделы «KNOWN HRDS COMPONENTS», «Mobile shell», 0b2/0d). Здесь — только то,
чего там нет: как именно превращать десктоп в мобилку и на чём это ломается.

## 1. Каркас мобильного кадра

- **Ширина 375** (десктоп 1440, header 72, `❇️ Sidebar` 300 / compact 64, контентная колонка 1140).
- **Высота** — по соседям в файле, не выдумывать: в спека-бордах «все мобилки 812, все десктопы 860»;
  в ветке «Мобильная версия» вьюпорты 375×843; в файле звонков шторки пинятся к 844.
- Оболочка собирается ТОЛЬКО свежими инстансами библиотеки (ключи — в `hrtech.md`, «Mobile shell»):
  `System / Status Bar / iPhone` (375×54) → `❇️ Header [mobile]` (375×72, бургер/поиск/колокол — настраивать,
  не дублировать) → `💠 Content · Header [mobile]` (бэк-линк, H1, опциональные табы) → контент →
  `Home Indicator` (375×21). Клонировать шапки с чужих экранов нельзя.
- Контролы на мобилке — Size M (40), это планка юзера.

**Честный вьюпорт (иначе просвечивает фон борда).** Клон мобильного кадра приезжает по высоте контента
(409–591), а у внешнего кадра заливки нет — под контентом видно тёмную секцию:
1. внешний FRAME: `clipsContent=true`, `layoutSizingVertical='FIXED'`, `resize(375, 812)`;
2. **ВНУТРЕННИЙ** фрейм (`Мои встречи · mobile` и т.п.) тоже `resize(375, 812)` — шаг, который забывают;
3. если внутри два `m-content` (первый — паспорт 156, второй — блок состояния): растягивать **ВТОРОЙ**
   (`layoutGrow=1`), первому вернуть `layoutGrow=0` + HUG. Растянешь первый — между паспортом и блоком
   провал на пол-экрана, а Home Indicator зависает посередине (юзер это ловит первым же зумом).
4. Выравнивание растянутого контейнера — `primaryAxisAlignItems='CENTER'` (см. болезнь 2).

**Вьюпорт «поплыл» после правок текста.** Экран 375×843 с VERTICAL авто-лейаутом РАСТЁТ от роста текста:
вернуть `primaryAxisSizingMode='FIXED'` + `resize(375,843)` + `clipsContent=true`, а Home Indicator
(он В ПОТОКЕ) → `layoutPositioning='ABSOLUTE'`, `y=843-h`, `constraints` MAX. Длинные скролл-моки
(2200–2800) растить можно. Скролльные кадры в спеке кропятся `clipsContent=true` + `resize`.

## 2. Карта «десктопный элемент → мобильный эквивалент»

| Горизонтальная группа полей | стопкой, gap 8 |

**Фильтры (сборка).** Ряд-обёртка: HORIZONTAL, padding 16, itemSpacing 8, `💠 Input · Search` `layoutGrow=1`,
справа `❇️ Button` Variant=Icon 40×40 `layoutGrow=0`. Глиф — воронка **`Filter : Alternative`**
`2da562ce5436fde28491c1787d75bc18a2f8e593`, НЕ ползунки `Filter` `182ac0032acdaa20d24d5c9a2c4f7c4e43858bf3`;
ставится в `← Icon#29143:237`. Инлайн-чипов и аккордеона «Фильтры» на мобилке нет. Категория открывается
одним из двух способов («Назад» внутри шторки — дефолт; «Поверх» стеком — для самодостаточной настройки),
правило выбора и антипаттерн — в `hrds-knowledge.md`.

**Размер чипов/контролов на мобилке задаётся МОДАМИ коллекций переменных**, не вариантом и не паддингом:
`Control` (`85da8517acefe13562cc01d6b0921e4708dffc00/23915:33`) → `Mobile` `19661:1`;
`🚫 Control · Size` (`682574d84cdb7825bd30c104bc92fd1eda96e0ef/49316:0`) → `M` `47640:1`;
`◇ · Размер` (`27a55b131a90a5c052d50366fff70e532ebe144c/68:12`) → `Small` `59:0` ⇒ 40 px.
`setExplicitVariableModeForCollection` **на каждом инстансе чипа** — с корня НЕ каскадится.
`_ 🚫 Tag · Filter` (`1388:5038`) жёстко залочен на 32 — не воевать, свапать на `❇️ Tag · Dropdown`
`5dcdae062ce66fceb1d8a6adc52767b3c76e01ce`.

**Меню действий.** У вложенного `❇️ Menu` (Preset=Menu `68b589d2ec4ed7eaa6133e08e6637038c532b514`) булевы
`Item · 1#39907:16` … `Item · 8#39907:58`; лейбл строки — TEXT-проп `← Label#19437:6` (РАБОТАЕТ, в отличие от
List-Item `← Title`); лидирующая иконка — сперва `Slot ←#24121:360` = `💠 Icon` `6b6c16fffd6e2c1f6707f0b12506efdcbc28b45c`,
ПОТОМ у неё `← Icon#616:5`; шапка — `has Slot ↑#26111:25` + `↳ Slot#26111:32` = `Dropdown / 💠 Text`
`4fa25e57c1e1c21cf7d7d4d7f8a56214e95a3000`, текст `← Description#26103:3`. `importComponentSetByKeyAsync('7c98…')`
**таймаутит** (сет огромный) — надёжнее клонировать готовый инстанс или шаблон-фрейм `Шторка · Действия` на List-Item.

> **Почему контент шторки обязан быть отдельным компонентом:** в ИНСТАНС нельзя `appendChild` —
> ни в `Drawer`, ни в строку списка. Поэтому кастомное тело шторки делается КОМПОНЕНТОМ и
> подставляется свапом, а дополнительное действие в строке вешается СИБЛИНГОМ, а не внутрь.

## 3. Настоящий `Drawer [mobile]` вместо рукодельной шторки

Рукодельный фрейм, косплеящий шторку (Pull-Bar + Header + кнопки внутри обычного FRAME), заменяется инстансом
компонента — высоты сходятся 1:1 (расхождение −12 px, если вместо `💠 H3` встаёт честный DS Header).
Пропы сета `4d65c84f…`: `has Header` / `has Pull-Bar` / `has Footer` / `has Scroll` + **`↳ Content#40337:2`
(INSTANCE_SWAP)**; заголовок `← Title#24902:21`, `↳ Subtitle#24902:22`, `has Subtitle#1519:6`, крестик
`has Slot#47406:9` / `↳ Slot#47404:5`.
1. `const d = set.defaultVariant.createInstance()`; выставить булевы переключатели.
2. `d.findOne(n => n.name === 'Media').visible = false` — у Media НЕТ пропа-тумблера, гасится видимостью.
3. **Контент — обязательно отдельный КОМПОНЕНТ** (`figma.createComponent()`, ширина ≈335 при Drawer 375 или
   FILL, vertical HUG, **скопировать paddingTop/Bottom и itemSpacing исходника** — иначе теряешь 24 px),
   припарковать вне канваса, наполнить, потом `d.setProperties({'↳ Content#40337:2': CONT.id})` и
   `← Content.layoutSizingHorizontal = 'FILL'`. У каждого экрана свой контент-компонент — это цена строгого ДС.
4. Кнопки футера (`Button · CTA` / `· 2` / `· 3`) — обычные `❇️ Button`. При конвертации собирать их **по
   СИГНАТУРЕ ПРОПСОВ, не по имени**: `footer.findAll(INSTANCE && visible && hasProp('View') &&
   hasProp('← Label') && hasProp('Variant'))`, сортировать по `absoluteBoundingBox.y`, маппить позиционно.
   В реальных файлах они звались «Button · 4» и лежали то в `Button · Group`, то прямо в Footer.
5. **Порядок `setProperties`: сначала ВСЕ булевы/вариантные переключатели (root, затем Footer), и только потом
   свежие `findOne` + тонкая настройка** — переключатели пересобирают поддерево, старые ссылки умирают
   («node does not exist»). Ключи пропов передавать по префиксу до `#` — id-суффиксы разнятся между файлами.
6. Пустая середина: прятать тот Container, у которого `children.some(x => x.name === '← Content')` —
   **ПРЯМОЙ** ребёнок. Рекурсивный `findOne` цепляет внешний Container, и шторка схлопывается до ручки 24 px.
7. Пиновать к низу: экран-хост обычно авто-лейаут → `d.layoutPositioning = 'ABSOLUTE'`, затем
   `d.y = screen.height − d.height` (без ABSOLUTE x/y игнорируются, инстанс встаёт в поток).
   После КАЖДОЙ правки контента перепинивать: `sheet.y = parent.height − sheet.height`.
   `Height=Hug` растит шторку ВНИЗ от своей y — иначе она уезжает за кадр.
8. Разделители внутри — `💠 Divider · H` `f0e478ae97d7967da21472af1112109e943daeb3`
   (вертикальный `d5c2a562847a830d4db45b8623aa7baba3ab4c98`) + `layoutSizingHorizontal='FILL'`, не сырой
   прямоугольник. Если ключ не импортится («Could not find a published component») — взять мастер с живого
   инстанса: `findOne(INSTANCE 'Divider')` → `getMainComponentAsync()`.
9. Шапки à la carte: `💠 H1–H4` (56/52/48/44), `H3` = `efc025969bcef01edfdb2ec337de7128ca30885f`, пропы те же,
   но у них **0 бокового паддинга** — задавать паддингом родителя. Крестик — ghost-иконка без фона, это и есть
   ДС-норма (серый кружок не подставлять). «‹ Назад» заведена в мастера H1–H4 (`has Back` + `↳ Back`, дефолт
   OFF); нет пропа в файле — старый обход через клон ✕ со свапом на `Arrow : Short : Left` `0ee960ea…`.
10. **Под шторкой обязателен скрим.** Голая шторка, приклеенная к низу, — незаконченный экран:
    `Backdrop` = прямоугольник на весь кадр, чёрный, прозрачность **0.4**. Три грабли:
    - **заливка с `opacity` ВНУТРИ paint не рендерится в экспорте** (скрим выглядит отсутствующим) →
      `fills = [{type:'SOLID', color:{r:0,g:0,b:0}}]` + `node.opacity = 0.4`;
    - если биндишь к токену `special/overlay`, помни: `setBoundVariableForPaint` подставляет только
      ЦВЕТ, прозрачность задаёшь сам (`paint.opacity = 0.48`), иначе скрим выходит почти чёрным.
      Импорт переменной — `figma.variables.importVariableByKeyAsync`, НЕ `figma.importVariableByKeyAsync`
      (падает «not a function»);
    - **z-order разный у десктопа и мобилки.** У десктопного кадра-авто-лейаута с
      `itemReverseZIndex = true` **`children[0]` рисуется СВЕРХУ** → оверлеи вставлять
      `insertChild(0, …)`, самый верхний первым. У мобильного кадра (`layoutMode` NONE) наоборот —
      сверху последний ребёнок. Детям-оверлеям обязателен `layoutPositioning = 'ABSOLUTE'`, иначе
      узел уезжает в поток.
11. Standalone **Pull-Bar схлопывается в высоту 0** — рисовать ручку самому: 36×4, r2, `#D1D1D6`. У
    `Dropdown [mobile]` встроенный Pull-Bar даёт ВТОРУЮ полоску 44×4 над шторкой — ручную оставить, встроенную
    скрыть. Оригиналы рукодельных шторок не удалять: `visible=false` в своём экране, на откат.

## 4. Типографика

**Никогда не ставь голые `fontSize`/`lineHeight`.** Текст сажается на ДС-стили:
`setRangeTextStyleIdAsync(start, end, styleId)` / `setTextStyleIdAsync`. Юзер: «надо использовать дизайн
систему, иначе нахера весь плагин»; собственные «best-practice» цифры получили оценку «кал, шрифты не по ДС».

- Локальных текст-стилей в рабочих файлах НЕТ (`getLocalTextStylesAsync()` = []) — они remote. Способа два:
  `importStyleByKeyAsync` по библиотечным ключам (список — в `hrtech.md`) **или** снять in-file id с соседнего
  текста: `node.textStyleId` → `getStyleByIdAsync(id)` → проверить name/fontSize → применить тот же id.
- Мобильная шкала: заголовок экрана `Title/L · Medium` 28 · заголовок строки/секции `Title/S · Medium` 20
  (финал после истории 18→16→14→**20**, назад не откатывать) · подзаголовки `Body/M · Medium` 16 ·
  тело и длинное чтение `Body/S` 14/20 (не `Body · Compact/S` 14/18 — «скомкано») · капшены `Caption/M` 12.
  **Ниже 14 на мобилке не опускаемся.** Иерархия «дата vs заголовок» — ЦВЕТОМ (дата серая 0.6, заголовок
  тёмный 0.88) и воздухом, а не размером. Ритм: внутри блока `space/XS` 8, между блоками `space/XL` 24.
- `setRangeTextStyleIdAsync` требует прогрузки шрифтов ренджа (`getRangeAllFontNames` → `loadFontAsync`) +
  YS Text Regular/Medium. План ренджей снимать ДО применения (styleId не меняет офсеты).
- **ГЛАВНАЯ ГОЧА пропагации:** range-level оверрайд стиля на инстансе перекрывает мастер НАВСЕГДА — потом
  «поправил размер в компоненте, а тут не обновился». Лечится проходом по всем TEXT: через ПОСЛЕДНИЙ сегмент
  id (`I…;src` → `src` = узел-исходник) достать `master.textStyleId` и переприменить (диф — по `fontSize`/
  `textStyleId` инстанса против мастера). Облачный Figma-MCP файл ЧИТАЕТ, но писать текст не может
  (`listAvailableFontsAsync` без YS Text) — только через мост Булочки.
- `💠 Input · Search` — remote read-only мастер: размер текста правится оверрайдом на каждом инстансе.
  Селекты месяца/года в календарной шторке при 16 транкейтятся («Янв…», «20…») — их оставлять 14.

## 5. Три системные болезни мобилок

1. **Голый текст вместо блока состояния.** Перенося состояние с десктопа, поднимайся от TEXT вверх до фрейма
   **`Component`**, а не останавливайся на вложенном инстансе `Text`. `Text` — это только заголовок+подзаголовок;
   `Component` (VERTICAL, `primaryAxisAlignItems='CENTER'`) держит ещё иллюстрацию **`No Action` 132×88** и
   **`Button · CTA`**. Из-за этой ошибки шесть мобилок жили без картинки и без кнопок.
   Клон → `layoutSizingHorizontal='FILL'` + `layoutSizingVertical='HUG'` + `resize(343, h)`, старый `Text`
   погасить. **Проверка парности:** у десктопа и мобилки одинаковый ответ на «есть ли внутри узел `No Action`».
2. **Блок прижат к верху.** `m-content` с `layoutGrow=1` и `primaryAxisAlignItems='MIN'` липнет под паспорт,
   под ним пол-экрана пустоты (на десктопе блок отцентрован). Ставить **`primaryAxisAlignItems='CENTER'`** —
   FAB это не задевает, он ABSOLUTE.
3. **FAB за экраном** (поймано сразу в 14 мобилках). Он ABSOLUTE с `y=1085`, унаследованным от высокого
   скролл-контейнера; после кропа до 812 оказывается ниже кадра. Правило:
   `y = 791 − 16 − 48 − (parent.absY − frame.absY)`, `x = 311`. С тостом: тост на низ `y=727`, FAB над ним
   `y=663` (сверху тост перекрывал заголовок). В другом файле та же формула словами: `y = низ − 34 (Home
   Indicator) − 16 − 48`; на экранах с баром «Полезно/Так себе» — над ним (`y = rowTop − 12 − 48`).

Сам FAB: `❇️ FAB` `59e3e29b11bf8d1ee84195b351d701b4e7614afd`, `Variant=—, View=Primary, Stack=off`; **размер и
иконка живут во ВЛОЖЕННОМ инстансе «Button»** — `Size=L` (48) и `← Icon#29143:237` → `Unsorted / Magic`
`335025c8f0694df13a713981bfea75bf226a038d` (`Size=24, Filled=true`), отдельными вызовами `setProperties`.
Цвет коралла — литерал `#E1624D` (токена в либе не нашли, уточнять у команды). **Ещё одна парная проверка:**
вкладки `⏳ TabsMenu` внутри `💠 Content · Header [mobile]` держать в том же состоянии, что на десктопе —
пропа у них нет, прячутся/показываются `visible`.

## 6. Гочи

- **ДС-тост на мобилке:** `Toast` приходит с `minWidth = maxWidth = 400`, поэтому `resize(343)` **молча** не
  срабатывает — ширина остаётся 400 и торчит за 375-й кадр. Лечение: `toast.minWidth = null` → `resize(343, h)`
  → `x = 16`.
- **Мобилку проверять СКРИНШОТОМ, а не дампом текстов** — подложка у всех мобилок одинаковая, различие сидит
  в ОВЕРЛЕЕ, а он в текст не попадает. Так под «Выбираю участников» стояла чужая шторка «Фильтры» — поймали только скриншотом.
  При этом `figma_capture_screenshot` **кеширует по nodeId+format** — повторный снимок того же узла вернёт
  старую картинку (виден одинаковый `byteLength`).
- **Клон вложенной иконки-кнопки приходит `visible=false`** — после `clone()` + reparent обязательно
  `btn.visible = true` (и у `Base`/`← Icon`). Иначе кнопка в ряду формально есть, но не рендерится, а поиск
  растягивается на всю ширину: скрытые дети авто-лейаута места не занимают.
- **Глифы HRDS через мост не достаются** (remote-библиотека, у моста нет REST-токена): `importComponentByKeyAsync`
  по ключу иконки → «Could not find a published component». Иконки харвестить с размещённых инстансов
  (`getMainComponentAsync`) или ставить временный локальный глиф и просить юзера подменить пикером в
  `← Icon#29143:237`. Рисовать иконку вектором — запрещено.
- `getMainComponentAsync` на remote-инстансах медленный — не гонять десятками в цикле (таймаут ~22 с).
- **`💠 List-Item`:** `Label`/`Caption` писать ТЕКСТ-узлами напрямую — проп `← Title` часто не применяется
  (остаётся плейсхолдер «Label»). Двух трейлинг-контролов (copy + call) он не держит — собирай ряд фреймом
  (`layoutGrow=1` у текста). «Значение крупно / тип мелко» — `Reserse='on'` у вложенного `Text · Leading`.
  Вариант `◇ List-Item · Inline` — на ОДНУ строку; для двух строк `Content='◇ List-Item'` и **явно** выставить
  паддинги 8 (оверрайд от клона переживает смену варианта).
- **Аватары.** Кластер участников — стек с отрицательным gap (−8) + «+N». В паспорте встречи строка
  «Участники» = аватар + «+» + группа из трёх (донор 129×32), а не голая стопка. Проверка паспорта:
  **число детей колонки лейблов == число детей колонки значений** — иначе значения уезжают на строку вниз
  («Дата» показывает аватарки).
- **Платформенные твики НЕ в общем мастере** (правка мастера ради мобильной строки ломает десктопные таблицы):
  instance-override · ось `Adaptive = Desktop | Mobile` (Mobile = структурный клон Desktop + `resize(375)` +
  скрыть ховер-элементы; **Mobile — не состояние**, на ось `State` не вешать) · сиблинг рядом с компонентом.
  Оверрайды между вариантами Figma мапит **ПО ИМЕНИ узла** → имена текст-узлов должны быть УНИКАЛЬНЫМИ во
  всех вариантах, иначе при репаренте контент путается.
- `layoutMode` вложенного инстанса переопределить НЕЛЬЗЯ — Figma игнорит при рендере. Мобильный инстанс
  класть в контейнер ≤375: вариант с интринзиком 375 в широком FILL-родителе растянется.
- Адаптация табличной ячейки: скрыть спейсер `← Size →` (держит ширину колонки 320); `layoutSizingVertical=
  'HUG'` — И ячейке, И родительскому враперу (одной мало, иначе дыра ~48 px); вариант в авто-лейаут сете —
  `layoutAlign='INHERIT'` + `layoutSizingHorizontal='FIXED'` + `resize(375)`; ошибка «absolute positioned»
  при FILL лечится `layoutPositioning='AUTO'`.
- Линия под строкой может быть не нодой, а **нижним бордером рута** (`strokeBottomWeight` 1, #000 @0.08) —
  скан по нодам её не видит, всегда проверяй `strokes` рута; «у последней строки группы линии нет» =
  `inst.strokes = []`.
- Клон текста: `resize(w,h)` СНАЧАЛА, `textAutoResize='HEIGHT'` ПОСЛЕ — иначе высота остаётся старой.
- Связь моста в тяжёлых файлах рвётся без фокуса вкладки («Unable to establish connection» / «Connection
  replaced»), но команда часто ВСЁ РАВНО выполняется — делай идемпотентные вызовы и проверяй результат
  чтением. Полный `findAll` по документу вешает песочницу: скан только по секции/кадру.
