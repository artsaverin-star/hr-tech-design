# Булочка · HR TECH DESIGN

Булочка — мост между Figma и ИИ-помощником дизайнера плюс база знаний HR Tech (HRDS, паттерны,
прод). Помощник может быть любым из поддерживаемых — **Codex CLI** или **Claude Code**: оба ходят в
один MCP `figma-hrtech` и читают одни и те же умения. Дизайнер ставит задачу словами там, где уже
работает каждый день — со своим аккаунтом, историей, лимитами и настройками модели.

Интерфейс Булочки в Figma — это не второй агент и не центр выполнения задач. В нём остаются две
понятные сущности:

- **каталог умений** — что помощник умеет сделать с HRDS, Figma и Прототипницей, когда умение
  подключается и какие данные ему нужны;
- **настройки** — связь с Figma, личный Figma-токен, состояние помощника, установка и обновление
  умений, версия и диагностика.

Булочка ничего не выполняет сама и ничего не запускает в фоне: кнопок-действий в ней нет, чужих
запусков она не показывает. Единственный путь — попросить помощника словами; работа и её прогресс
живут в его задаче.

## Умения HR Tech

Пакет Булочки даёт помощнику специализированные умения:

- **`hrtech-mobile`** — desktop → mobile 375 по компонентам и правилам HRDS;
- **`hrtech-audit`** — аудит и исправление макета на соответствие HRDS;
- **`hrtech-spec`** — сборка и проверка спецификации сценариев;
- **`hrtech-prototipnitsa`** — Figma-спека → живой прототип в Прототипнице;
- **`hrtech-proto-spec`** — живой прототип → синхронизированная Figma-спека;
- **`hrtech-arcadia`** — продуктовый код и тексты как источник правды.

Общие правила, знания HRDS и командные рецепты версионируются вместе с умениями. Помощник выбирает
подходящее умение по описанию задачи или дизайнер вызывает его явно по имени. Формат — обычные
локальные skills, их одинаково читают и Codex ([док](https://learn.chatgpt.com/docs/build-skills)),
и Claude Code.

## Почему это работает для большой команды

У каждого дизайнера свой помощник и своя задача, а Булочка не выполняет задачи и не запускает ничего
в фоне — значит, нечему упираться в сотню дизайнеров или сотню Figma-файлов. Командными остаются
только версии умений и базы знаний; аккаунт, контекст разговора, разрешения и выполнение остаются
локальными у дизайнера.

Умение обращается через MCP к тому Figma-файлу, который открыт у дизайнера. Булочка показывает связь
и помогает её настроить, но не переносит выполнение в отдельный скрытый агент.

## Установка

Самый простой вариант для дизайнера — одна команда:

```bash
curl -fsSL https://raw.githubusercontent.com/artsaverin-star/hr-tech-design/main/install.sh | bash
```

Установщик находит уже установленного помощника (Codex CLI или Claude Code), а если помощника нет —
ставит Codex CLI. Дальше он подключает мост `figma-hrtech` и умения HR Tech ко всем найденным
помощникам, скачивает проект в `~/hr-tech-design` и открывает папку плагина.

После установки нужно один раз:

1. Войти в своего помощника: Codex — запустить `codex` в Терминале и войти в аккаунт ChatGPT;
   Claude Code — запустить `claude` и войти как обычно.
2. В desktop Figma открыть **Plugins → Development → Import plugin from manifest…** и выбрать
   `~/hr-tech-design/figma-desktop-bridge/manifest.json`.

## Каждый день

1. Открой рабочий Figma-файл и запусти **Булочку / HR TECH DESIGN**.
2. В каталоге умений при необходимости посмотри нужное умение и пример постановки задачи.
3. Поставь задачу обычными словами своему помощнику. Например: «переведи выделенный экран на mobile
   375 по HRDS» или «собери из этой спеки прототип в Прототипнице».
4. Когда помощник начнёт работать с Figma, в Булочке появится статус подключённого моста.
5. Оставь Figma-файл и Булочку открытыми, пока помощник работает с макетом.

Модель, настройки, разрешения, прогресс и остановка живут у самого помощника. Булочка их не
дублирует.

## Если не работает

- В Булочке открой **Настройки** и проверь связь с Figma, помощника и версию умений.
- Проверь, что мост подключён: Codex — `codex mcp list`, Claude Code — `claude mcp list`;
  в списке должен быть `figma-hrtech`.
- Если моста или умений нет, запусти `cd ~/hr-tech-design && ./setup.sh`, затем перезапусти
  помощника.
- Если Figma не отвечает, закрой и заново открой Булочку в нужном файле.

## Как дополнять знания

База знаний — версионируемый источник правды в репозитории:

- `claude/commands/hrtech.md` — общий протокол выполнения и правила сборки;
- `claude/commands/hrds-knowledge.md` — справочник компонентов и паттернов HRDS;
- `claude/skills/` — исходники умений; их читают оба помощника (Codex и Claude Code);
- `claude/knowledge/team-notes.md` — подтверждённые наработки команды.

Подробнее для разработчиков — в `CLAUDE.md`, для дизайнеров — в `ONBOARDING.md`. Процесс
контрибуции в саму HRDS описан в `HRDS-CONTRIBUTION.md`.
