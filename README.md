# Булочка 4.30 · HR TECH DESIGN

Булочка — мост между Figma и ИИ-помощником дизайнера плюс база знаний HR Tech (HRDS, паттерны,
прод). Помощник может быть любым из поддерживаемых — **Codex** или **Claude Code**: оба используют
MCP `figma-hrtech` и читают одни и те же умения. Дизайнер ставит задачу словами там, где уже
работает каждый день — со своим аккаунтом, историей, лимитами и настройками модели.

Интерфейс всегда тёмный, независимо от темы Figma. Под навигацией на обоих экранах видна одна
строка состояния: подключено, подключается, нет подключения, пауза или несовпадение версий.
В нём два экрана:

- **Главная** — короткое описание и простой список из шести примеров запросов: с чем поможет
  Булочка и как попросить об этом помощника.
- **Настройки** — подключение и помощь при сбое, версия, найденные помощники, количество умений
  HR Tech, необязательный Figma-токен, обновление и отчёт для поддержки.

Задачу запускает запрос в чате помощника. Там же остаются прогресс и остановка работы.
Примеры на Главной помогают сформулировать запрос; сами макет не меняют.

## Умения HR Tech

Пакет Булочки даёт помощнику специализированные умения:

- **`hrtech-mobile`** — desktop → mobile 375 по компонентам и правилам HRDS;
- **`hrtech-audit`** — аудит и исправление макета на соответствие HRDS;
- **`hrtech-spec`** — сборка и проверка спецификации сценариев;
- **`hrtech-prototipnitsa`** — Figma-спека → живой прототип в Прототипнице;
- **`hrtech-proto-spec`** — живой прототип → синхронизированная Figma-спека;
- **`hrtech-arcadia`** — продуктовый код и тексты как источник правды.

Общие правила, знания HRDS и командные рецепты версионируются вместе с умениями. Помощник выбирает
подходящее умение по описанию задачи или дизайнер вызывает его явно по имени. Формат — обычные
локальные skills, их одинаково читают и Codex ([док](https://learn.chatgpt.com/docs/build-skills)),
и Claude Code.

## Почему это работает для большой команды

У каждого дизайнера свой аккаунт помощника и локальный мост на его Mac. Сервер владельца Булочки
и общий аккаунт команды не нужны. Общими остаются версии умений и базы знаний; мост работает с
Figma-файлом, который открыт у конкретного дизайнера.

## Установка

В настройках плагина нажмите **«Скопировать команду»**, вставьте скопированную команду в Терминал и нажмите Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/artsaverin-star/hr-tech-design/main/install.sh | bash
```

Команда скачивает и проверяет пакет, сохраняет собственный движок в `~/Library/Application Support/Bulochka` и настраивает найденные Codex и Claude Code. Отдельное приложение, Git, Homebrew, Xcode и системный Node не нужны. Требуется macOS 13.5 или новее и установленный помощник.

После первой настройки откройте новый чат помощника и попросите: «Подключись к Figma через Булочку и назови открытый файл. Ничего не меняй». Оставьте плагин открытым.

Повторный запуск этой же команды восстанавливает подключение и обновляет пакет. При доступном мосте используйте **«Обновить»** в плагине: Терминал для этого не нужен. Новая версия моста подхватывается между командами с сохранением MCP-соединения и привязки к файлу.

## Каждый день

1. Открой рабочий Figma-файл и запусти **Plugins → From Yandex → Bulochka**.
2. На **Главной** выбери подходящий пример или сформулируй свою задачу.
3. Выдели экран в Figma и поставь задачу в чате Codex или Claude Code. Например: «переведи выделенный экран на mobile
   375 по HRDS» или «собери из этой спеки прототип в Прототипнице».
4. При необходимости проверь подключение в **Настройках**.
5. Оставь Figma-файл и Булочку открытыми, пока помощник работает с макетом.

Модель, настройки, разрешения, прогресс и остановка живут у самого помощника. Булочка их не
дублирует.

## Если не работает

1. Откройте **Настройки → Скопировать команду** и выполните скопированную команду в Терминале. Она восстановит локальный пакет и настройки помощников.
2. После первой настройки откройте новый чат помощника. Оставьте нужный файл и Булочку открытыми в Figma.
3. Если проблема осталась, нажмите **«Скопировать отчёт»** и передайте его вместе с ошибкой из чата. Без соединения плагин не может проверить файлы на Mac.

Версия самого плагина Figma распространяется через каталог Yandex. Локальный импорт `figma-desktop-bridge/manifest.json` нужен только разработчику для проверки неопубликованной версии.

## Как дополнять знания

База знаний — версионируемый источник правды в репозитории:

- `claude/commands/hrtech.md` — общий протокол выполнения и правила сборки;
- `claude/commands/hrds-knowledge.md` — справочник компонентов и паттернов HRDS;
- `claude/skills/` — исходники умений; их читают оба помощника (Codex и Claude Code);
- `claude/knowledge/team-notes.md` — подтверждённые наработки команды.

Подробнее для разработчиков — в `CLAUDE.md`, для дизайнеров — в `ONBOARDING.md`. Процесс
контрибуции в саму HRDS описан в `HRDS-CONTRIBUTION.md`.
